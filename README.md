# Momenta

Content planner and reel auto-generator for Indonesian UMKM and solo creators. See
[PRD.md](./PRD.md) for product scope, [CLAUDE.md](./CLAUDE.md) for the engineering
standard, and [docs/](./docs/) for tickets and requirements.

## Stack

TypeScript monolith: Next.js (App Router, frontend and backend in one codebase),
PostgreSQL via Prisma, BullMQ + Redis for background jobs, Docker Compose for local
infrastructure. See [PRD.md §11](./PRD.md#11-tech-stack-terkunci) for the locked
rationale.

## Prerequisites

- Node.js 24+
- Docker and Docker Compose

## First-time setup

```bash
cp .env.example .env
npm install
docker compose up -d postgres redis minio
npm run db:migrate
```

`npm install` runs `prisma generate` implicitly the first time you run any `db:*` or
`build` script; the generated client lands in `src/generated/prisma` (git-ignored,
regenerated on demand - see `db:generate` below to run it explicitly).

## Development

```bash
npm run dev          # Next.js app on http://localhost:3000
npm run dev:worker    # BullMQ worker, hot-reloading
```

Both processes read `.env` directly. Run `docker compose up -d postgres redis minio` first
(only the infrastructure, not `web`/`worker` - those run locally in this flow).

## Running the full stack in Docker

```bash
docker compose up --build
```

Starts `web`, `worker` (same image, different command - see `Dockerfile` and
`docker-compose.yml`), `postgres`, `redis`, and `minio`. The app is reachable at
`http://localhost:3000`; `GET /api/v1/health` reports whether Postgres and Redis are
reachable from inside the container network, and each dependency check has its own
2-second timeout so an outage degrades to a `503` instead of hanging the request.

## Quality gate

```bash
npm run format:check
npm run lint
npm run typecheck
npm run test               # unit tests, fakes only, no external services required
npm run test:integration    # real Postgres + Redis; run `docker compose up -d postgres redis` first
npm run test:e2e            # Playwright; builds and starts the app itself
npm run verify              # format:check + lint + typecheck + test, in order
```

## Database

Prisma schema lives in `prisma/schema.prisma`; CLI connection configuration (used by
`prisma migrate`/`generate`, not by the running app) lives in `prisma.config.ts`.

```bash
npm run db:generate          # regenerate the Prisma client
npm run db:migrate           # create and apply a migration in development
npm run db:migrate:deploy    # apply pending migrations, no schema drift check (CI/production)
npm run db:studio            # browse data
```

The app itself never reads `DATABASE_URL` through the Prisma CLI convention - it builds a
`@prisma/adapter-pg` connection explicitly in `src/shared/database/prismaClient.ts` from
the validated config in `src/shared/config/env.ts`.

## Project layout

```
src/
  app/                Next.js routes, pages, and layouts (the HTTP boundary)
  modules/            Feature modules: controller -> service -> repository, one folder each
  shared/             Envelope, error taxonomy, logging, queue, database, config, async utils
  components/          Presentational React components
  styles/              Design tokens (src/styles/tokens.css), imported once from globals.css
  worker.ts            BullMQ worker process entrypoint (same image as web, different CMD)
  generated/prisma/    Prisma client output (git-ignored, regenerated by `db:generate`)
e2e/                  Playwright end-to-end specs
```

Dependencies point one direction only:
`route -> controller -> service -> repository -> database`. See
`.claude/skills/backend-standard/references/architecture.md`.
